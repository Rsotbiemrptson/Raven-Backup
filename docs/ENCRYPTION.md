# Optional encryption, passwords and schedules (1.8.0)

Encryption defaults off. In Settings → Backup preferences, use **Backup password**, then enable **Encrypt future backups**. Manual confirmation also offers a per-run encryption switch. Unencrypted archives remain ordinary ZIPs; encrypted archives use `AppName_MM-DD-YYYY.rbk` (same-day versions append `_2`, etc.). Open encrypted archives in Raven 1.8.0 or newer, not a generic ZIP tool. Existing formats 1–5 remain readable. All backups remain independent full backups; there are no incremental chains.

Use 8–1024 characters, preferably a long unique passphrase, and keep a separate copy. There is no recovery/reset option for a forgotten backup password. Changing the configured password only affects future archives. Older backups still require their original passwords. Filenames reveal the app name/date and the physical file size remains visible.

**Remember password on this device** is an explicit switch, off each time the password dialog opens. When enabled, Android Keystore wraps the password for unattended backups after the primary user has unlocked the device. The key and saved password do not transfer to another device or survive clearing Raven data, uninstalling or resetting the device. The password is never included in settings exports, archive metadata, root commands or logs. With Remember off, manual backups can use the password during the current app session.

A configured schedule triggers a reminder when adding/changing a password, with **Enable Remember** or **Keep off**. Scheduling also explains whether encryption is active and how remembered passwords work. Encrypted schedules require a saved password; they report the problem and create no archive if it is unavailable. They never silently fall back to plaintext. Plain schedules do not need a password. Imported schedules remain disabled until reviewed.

Opening a locked archive prompts for its original password. Unlocking it does not change the password for future backups. Session credentials remain available until **Lock encrypted backups**, app-process exit or device restart. An already-reviewed restore holds its password until that plan is closed. **Forget saved password** clears both session passwords and the optional device-stored password; archives stay unchanged. Keep your own password before forgetting it.

The encrypted output is streamed directly to the destination. Restore decrypts authenticated segments on demand through a seekable Android file view, without creating a full plaintext copy of the ZIP. As with plaintext restore, private TAR work files, restored external staging folders and private recovery ZIPs are not encrypted by this feature; they remain protected by their existing Android permissions. Recovery ZIPs still contain private data only. Optional full verification adds a complete read of the payload. Large backups still take time and require staging/recovery space.

## Maintainer format reference

The 32-byte envelope contains ASCII `RVNENC01`, a random 16-byte PBKDF salt, big-endian integer 600000 and reserved integer zero. PBKDF2-HMAC-SHA256 derives a 256-bit input key. Google Tink 1.24.0 `AesGcmHkdfStreaming` uses HMAC-SHA256, AES-256 and 1 MiB ciphertext segments, with zero first-segment offset. The complete envelope is authenticated as associated data; Tink supplies per-stream salt/nonces and authenticated final-segment framing. Maximum inner ZIP size is 544 GiB; existing per-payload and external limits still apply. Unsupported parameters and wrong passwords fail closed. Full validation authenticates unread segments as well as validating archive structure, CRCs, TAR paths and manifest hashes before target data replacement.

The read-only ZIP/ZIP64 index accepts stored/deflated entries with strict bounds, duplicate/path checks and no multi-disk/legacy ZIP encryption support. It uses an existing seekable channel instead of reopening Android's one-open proxy inode. Nonseekable encrypted providers are unsupported; choose local/internal storage or a portable card.

Dependencies and hashes are pinned in `libs/DEPENDENCIES.json`. See [Tink streaming design](https://developers.google.com/tink/streaming-aead/aes_gcm_hkdf_streaming), [Android proxy descriptors](https://developer.android.com/reference/android/os/storage/StorageManager#openProxyFileDescriptor(int,%20android.os.ProxyFileDescriptorCallback,%20android.os.Handler)), and the [ZIP specification](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT).
